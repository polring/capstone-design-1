# Text-to-SQL 1단계 진행 보고서

작성일: 2026-09-20

## 개요

from-scratch Text-to-SQL Transformer 프로젝트의 1단계(단일 테이블, 단일 WHERE 등호 SQL)는 데이터 생성 파이프라인과 BPE 토크나이저 구현까지 완료했고, 모델·학습 루프 구현을 앞두고 있다.

| 순서 | 작업 | 완료 조건 | 상태 |
| --- | --- | --- | --- |
| 1 | DB 생성기 구현 | 분포 조건·결정성·price 등호 비교·미등장 값 분리 4종 테스트 통과 | 완료 |
| 2 | SQL 생성기 구현 | 전체 SQL 오류 없이 실행, 구조별 할당량 재현 가능, ID 조건 비중 30% 이하 | 완료 |
| 3 | 사람 작성 평가 질문 200개 작성·봉인 | 1단계 범위 내 질문 구성 | 보류 |
| 4 | LLM 질문 생성 파일럿 | 자동 검증 통과율 90% 이상 | 완료 (13라운드, 23,045/23,045쌍 100%) |
| 5 | BPE 토크나이저 구현 | 전체 SQL round-trip 정확 복원, 미등장 이름 평균 분할 토큰 수 측정 | 완료 |
| 6 | 모델·학습 루프 구현 | 학습 예시 100개 과적합 테스트 100% 정확도, GPU 실효 처리량 실측 | 예정 |
| 7 | 전체 데이터 생성 (분포 내 평가 질문 포함) | 자동 검증 통과, 수동 감사 라벨 오류율 2% 이하 | 완료 (SQL 1,154개 + 질문 5,770개, 검증 통과율 100%) |
| 8 | 학습·평가·ablation | 3-5 기준 판정 | 예정 |

## 데이터 파이프라인 코드 구성

네 개 파이썬 파일이 데이터 생성부터 토크나이징까지를 담당한다. 둘 다 외부 토크나이저/모델 라이브러리 없이 표준 라이브러리만으로 짜여있다.

| 파일 | 역할 | 핵심 함수 |
| --- | --- | --- |
| `db/db_gen.py` | 고정 스키마의 SQLite 샵 DB 생성 (customers 300·items 200·orders 500행), 미등장 값 분리 | `build`, `balanced_column`, `canonical_hash`, `build_holdout` |
| `db/sql_gen.py` | DB 값을 기반으로 학습·평가용 SQL 생성, holdout 리터럴 제외 | `build`, `verify`, `summary` |
| `db/question_gen.py` | SQL을 자연어 질문과 짝짓는 LLM 프롬프트 생성·응답 검증 파이프라인, 라운드별 누적 | `make-prompts`, `validate`, `template-check` |
| `bpe_tokenizer.py` | 스크래치부터 구현한 byte-level BPE 토크나이저: seed 토큰 38개(SQL 키워드·컬럼명·카테고리/상태 값) + 병합 726개까지 vocab 1,024 구성 | `pre_tokenize`, `train`, `encode`, `decode`, `save_merges`/`load_merges` |

이 중 `db/db_gen.py`·`sql_gen.py`·`question_gen.py`는 완료되어 있고, `bpe_tokenizer.py`는 이번에 학습·검증까지 끝난 상태다.

## 데이터셋 규모와 형태

학습용 (질문, SQL) 쌍은 **23,045개**(SQL 4,609종 × 질문 5개), 자동 검증 통과율 100%다.

**DB 규모** (`shop.db`)

| 테이블 | 행 수 | 비고 |
| --- | --- | --- |
| customers | 300 | customer_id 1000대, name/city/membership |
| items | 200 | item_id 3000대, item_name/category/price/stock |
| orders | 500 | order_id 5000대, N:M 브리지 |

**SQL · 질문 규모**

| 구분 | 개수 | 비고 |
| --- | --- | --- |
| `sql_train.json` | 4,609 | 고유 학습 SQL |
| `sql_eval_indist.json` | 1,154 | 분포 내 평가용 SQL — 질문 5,770개(1,154×5) 완료, 검증 통과율 100% |
| 학습용 (질문,SQL) 쌍 | 23,045 | pilot~pilot13 13라운드 누적 |

**holdout.json — 미등장 값 3계층**

| 층 | 대상 | 규모 | 측정 목적 |
| --- | --- | --- | --- |
| 개체 미등장 | 이름+ID 모두 미등장 | 고객 60명, 상품 40개 | 처음 보는 개체 전반 |
| ID만 미등장 | 이름은 등장, ID만 미등장 | 고객 30개, 상품 20개 | 숫자 복사 능력만 분리 |
| 주문 ID 미등장 | order_id | 50개 | 위와 동일 |

**SQL 구조별 분포 (상위 발췌)** — `sql_gen_report.json` 기준, WHERE 컬럼별 학습/평가 분할

| 테이블 | WHERE 컬럼 | 전체 SQL | 학습 | 평가 |
| --- | --- | --- | --- | --- |
| customers | name | 1,200 | 960 | 240 |
| customers | customer_id | 295 | 236 | 59 |
| items | price | 1,194 | 955 | 239 |
| items | item_name | 960 | 768 | 192 |
| items | stock | 528 | 422 | 106 |
| items | item_id | 354 | 283 | 71 |
| orders | customer_id/item_id/order_id | 각 354 | 각 283 | 각 71 |

ID 조건 비중은 30% 캡으로 제어되어 있어, 모델이 ID 첫 자리만 보고 테이블을 맞히는 지름길을 타지 않도록 설계되어 있다.

## BPE 토크나이저 규칙

vocab 1,024개 전체를 네 구간으로 고정 배치하고, 실제 학습은 726개 병합 예산을 다 써서 끝났다.

| ID 구간 | 개수 | 내용 |
| --- | --- | --- |
| 0~255 | 256 | UTF-8 바이트 값 그대로 (byte-level base) |
| 256~259 | 4 | 특수 토큰 `<pad> <bos> <eos> <sep>` |
| 260~297 | 38 | seed 토큰 — SQL 키워드·컬럼명·카테고리/상태 값 (통짜로 1토큰, 병합 대상 아님) |
| 298~1023 | 726 | 코퍼스 빈도 기반 학습 병합 (`MERGE_BASE = SEED_BASE + len(SEED_TOKENS)`로 자동 계산, off-by-one 없음) |

**학습 방식**: `pilot`~`pilot13`의 (질문, SQL) 46,090개 문자열을 코퍼스로 쓰고, seed가 아닌 조각만 UTF-8 바이트로 풀어 인접 쌍 빈도를 반복 측정·병합하는 표준 BPE. 동점은 사전순 최솟값 규칙으로 항상 같게 깨짐(결정성 보장).

**검증 결과**

| 항목 | 결과 |
| --- | --- |
| 병합 사용량 | 726 / 726 (예산 전부 소진) |
| 전체 코퍼스 round-trip | 46,090 / 46,090 정확 복원 (실패 0건) |
| 미등장 이름 평균 분할 토큰 수 | holdout 개체 미등장 풀(고객 60+상품 40=100개) 기준 **3.49토큰/이름** — 계획문서의 임계치(4토큰) 미만 |

round-trip 완전 복원으로 5번 작업의 완료 조건 1을, 평균 토큰 수 3.49로 완료 조건 2를 충족한다. (계획문서 3-5절 표의 "미등장 48명"은 학습용 holdout 전체 풀(100개)과는 별개로, 평가 질문 세트 생성 시의 계획치라 아직 확정된 서브셋은 없음.)

## 다음 단계

**6번 모델·학습 루프 구현**이 바로 다음 작업이다. 1단계 스펙: 6층 / 256차원 / 4헤드, 파라미터 약 5.02M, vocab 1,024(토크나이저와 일치), 컨텍스트 128. 완료 조건은 학습 예시 100개 과적합 테스트 100% 정확도 도달과 RTX 4070 Super 실효 처리량 실측.

PyTorch가 아직 환경에 설치되어 있지 않아, CUDA 빌드 설치가 선행돼야 한다.

**보류 중인 항목** (8번 학습·평가 전까지만 해결하면 됨)

- 사람 작성 평가 질문 200개 (3번)

학습 루프 구현과는 독립적으로 진행 가능하다.

## 후속 진행 (2026-09-21)

위 "다음 단계"에서 지적한 PyTorch 미설치 문제를 해결했다 — `.venv` 가상환경을 만들고 CUDA 빌드(cu130)로
PyTorch 2.14.0을 설치, RTX 4070 Super 인식과 실제 GPU 연산(matmul)까지 확인했다. `requirements.txt`로
재현 가능하게 고정해뒀다.

6번(모델·학습 루프 구현) 진입 전 선행 작업으로 `dataset.py`(PyTorch `Dataset`)를 새로 구현·검증했다 —
학습 23,045쌍 + 분포 내 평가 5,770쌍, 총 28,815쌍을 `<bos> question <sep> sql <eos>` 형식으로 토큰화하면
길이가 23~64토큰(평균 38.2)으로 컨텍스트 128에 전부 들어간다(초과 0건). `collate_fn`이 배치별 동적
패딩(고정 128 대비 연산 낭비 절감)과 SQL 부분만 loss를 계산하는 마스킹을 구현하며, 둘 다 자동 검증을
통과했다.

이 작업 도중 `BPE-tokenizer.py`를 `bpe_tokenizer.py`로 리네임했다 — 하이픈이 든 파일명은 파이썬 모듈로
import가 안 돼서, `dataset.py`가 토크나이저 함수를 가져다 쓰려면 필요한 변경이었다. 이 보고서의 위 표·
본문에 있던 옛 파일명은 이 변경을 반영해 고쳐뒀다.

문서도 정비했다: 5개 파이썬 파일(`db_gen.py`/`sql_gen.py`/`question_gen.py`/`bpe_tokenizer.py`/
`dataset.py`)의 함수별 입출력을 정리한 `function-reference.md`를 새로 만들었고, `.gitignore`·
`requirements.txt`도 새로 추가했다. `CLAUDE.md`/`SETUP.md`/계획서도 이 변경사항에 맞춰 갱신했다.

**팀 구성**: 이 보고서의 1~7번 작업은 4인 팀 중 팀원1(데이터 정제 → BPE 토크나이저 → Dataset →
`train.py`, 즉 학습 파이프라인 전담) 담당분이다. 모델 내부(임베딩+RoPE는 팀원2, 디코더 블록은 팀원3)와
C/C++ 추론 엔진(팀원4)은 별도 담당자 몫이며, 이 보고서 범위 밖이다.
