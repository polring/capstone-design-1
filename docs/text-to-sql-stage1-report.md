# Text-to-SQL 1단계 진행 보고서

최종 갱신: 2026-10-07

1단계 범위는 단일 테이블, `SELECT` 컬럼 하나 또는 `*`, `WHERE` 등호 조건 하나다. 본문은 결과(1절), 남은 오답의 원인(2절),
실험에서 얻은 결론(3절), 2단계로 넘기는 것(4절), 계획과 달라진 점(5절)이고, 실험 세부·설정·진행 내역은 부록에 있다.
작업별 완료 조건은 [계획서](text-to-sql-llm-project-plan.md) 3-3절, 실행 방법은 [SETUP](SETUP.md)에 있다.

## 요약

데이터 생성 → 토크나이저 → 모델 → 학습 → 평가 → 추론까지 1단계 파이프라인 전체가 동작한다. 5M 모델이 학습에 없던 SQL은
약 96.5%(라벨이 규칙과 다른 평가 문항을 빼면 97.5%), 처음 보는 이름·ID는 약 90% 맞힌다. 전환 기준(분포 내 98%,
미등장 값 90%)은 넘지 못했다.

학습 방식(정규화, EMA, 위치 토큰)을 바꿔도 단일 모델 수치는 더 오르지 않았다. 남은 오답은 학습 데이터에 적게 나온 질문
유형(존재 확인 등)과 평가셋 라벨 불일치에서 나온다. 이 원인은 2단계 질문 조합기에서 고치는 것이 효율적이라 **기준 미달인
채로 2단계로 넘어간다**(2026-10-07, 4절).

| 순서 | 작업 | 상태 |
| --- | --- | --- |
| 1 | DB 생성기 구현 | 완료 |
| 2 | SQL 생성기 구현 | 완료 |
| 3 | 사람 작성 평가 질문 200개 작성·봉인 | 2단계로 미룸 |
| 4 | LLM 질문 생성 파일럿 | 완료 |
| 5 | BPE 토크나이저 구현 | 완료 |
| 6 | 모델·학습 루프 구현 | 완료 |
| 7 | 전체 데이터 생성 | 완료 (자동 검증 기준, 수동 감사 미실시) |
| 8 | 학습·평가·ablation | 학습·평가·학습 방식 실험 완료, 전환 기준 미달. 모델 축소 ablation, 제약 디코더는 2단계에서 |

## 1. 전환 기준 결과

기본 모델(이름 교체 40% + 라벨 정제 데이터, `runs/stage1_ffn683_swap40`)을 seed 3개로 학습했다. seed 0 모델이 배포 모델 `models/stage1/`이다. 제약 디코더는 적용하지 않았다.

| 평가 | 쌍 수 | 목표 | EM (seed 0 / 1 / 2) | 판정 |
| --- | --- | --- | --- | --- |
| 분포 내 (학습에 없던 SQL), 규칙 일치 문항 | 5,142 | ≥ 98% | 97.7 / 97.3 / 97.4% | 미달 |
| └ 참고: 전체 문항 | 5,202 | | 96.7 / 96.3 / 96.4% | |
| 미등장 개체 (처음 보는 이름·ID) | 1,480 | ≥ 90% | 90.2 / 90.2 / 88.6% | 경계 |
| 미등장 ID (이름은 학습에 있고 ID만 처음) | 497 | ≥ 90% | 89.7 / 88.9 / 89.7% | 미달 |
| 미등장 주문 ID | 249 | ≥ 90% | 96.0 / 94.4 / 95.2% | 통과 |
| 새 말투 (GPT가 직접 쓴 프롬프트, 채택 전) | 2,500 | ≥ 90% | 86.4 / 85.9 / 84.4% | 미달 |
| 사람 작성 | — | ≥ 70% | 미측정 | 2단계로 미룸 |

- **분포 내는 규칙 일치 EM으로 판정한다.** 평가셋 중 60문항은 정답 라벨이 라벨 규칙(계획서 4-5)과 반대라, 규칙대로 답한
  모델이 오답 처리된다(2절). 이 문항을 뺀 EM으로 판정하고 전체 EM도 함께 적는다. 미등장 값 평가셋은 규칙을 만든 뒤
  재생성해 이런 문항이 없다. 판정 기준을 바꾼 이유는 5절에 있다.
- **미등장 개체는 통과로 보지 않는다.** seed 0의 95% 신뢰구간이 [88.6, 91.6]으로 90%에 걸치고, seed 하나는 88.6%다.
- **이름 복사는 크게 개선됐다.** 처음 보는 이름 정답률이 이름 교체 없이는 고객 0.3% · 상품 0.0%, 이름 교체로는 88.1% · 88.5%다.
- **새 말투 점수는 평가셋을 만든 프롬프트에 크게 좌우된다.** 같은 SQL에서 GPT 85.6%, 학습용과 비슷한 프롬프트를 쓴 Gemini
  97.2%였다(부록 A-3). 출처가 아직 GPT 하나뿐이라 채택 전이다.
- 다중 정답 EM(`*`와 이름 컬럼 중 무엇을 원하는지 질문에 단서가 없으면 둘 다 정답)은 분포 내 97.3%, 미등장 값 90.7%다.

## 2. 남은 오답의 원인

오답은 대부분 SELECT 컬럼 선택이다(분포 내 173개 중 112개, 미등장 값 206개 중 171개). 원인별로 나누면 다음과 같다.

| 원인 | 근거 | 해결 위치 |
| --- | --- | --- |
| **존재 확인(L1) 질문이 학습에 적다** | 존재 확인 비율이 학습 데이터 8~14%, 미등장 평가셋 20~25%. 세 seed가 모두 틀린 미등장 오답 141개 중 62개. 새 말투에서도 존재 확인 EM 75%(Claude 말투 97%) | 2단계 조합기에서 비율 조정, 채점 방식 결정 |
| **평가셋 라벨이 규칙과 다르다** | 라벨 규칙(계획서 4-5)으로 평가셋은 정제하지 않았다. 규칙과 다른 문항이 분포 내 60개이고(미등장 값 평가셋은 규칙을 만든 뒤 재생성해 0개), 세 seed 공통 분포 내 오답 98개 중 47개가 여기 속한다 | 분포 내는 규칙 일치 EM으로 판정(1절). 2단계 조합기는 규칙대로 라벨을 만듦 |
| **복수형 속성 명사가 학습에 없다** | "which quantities were ordered on orders with customer id 1165?" 같은 질문(새 말투 EM 10%). 학습 데이터에서 이런 복수형이 SELECT 컬럼을 가리키는 경우는 0~4번 | 2단계 조합기에 복수형 표현 추가 |
| **테이블 단서가 약하다** | 주문 단서가 있는데 customers로 답하거나("any purchases by customer 1610?"), 고객·상품 이름을 혼동. 세 seed 공통 오답 중 미등장 29개, 분포 내 23개 | 2단계 조합기에서 L4·L5 표현 보강 |

측정의 한계도 있다. 미등장 값 오답이 소수 SQL에 몰려 있어 쌍 단위 신뢰구간은 실제보다 좁다. 평가셋에는 숫자가 둘 이상인
질문, 긴 숫자, 따옴표로 감싼 값이 없는데, `python -m src.run --input "..."`으로 시험해 보면 이런 질문에 약하다.

## 3. 실험에서 얻은 결론

기본 모델과 같은 데이터·구조·학습 스케줄에서 학습 방식만 바꿨다. 세부 결과는 부록 A에 있다.

| 설정 | 분포 내 (규칙 일치) | 미등장 값 | 비고 |
| --- | --- | --- | --- |
| 기본 모델 (seed 3개 평균) | 97.5% | 90.3% | |
| EMA 0.9995 (seed 3개 평균) | 97.5% | 90.9% | 단일 모델 중 가장 안정적. 세 seed 모두 미등장 90% 이상 |
| 3-seed 앙상블 | 98.3% | 91.3% | 참고용. 게이트 판정에 쓰지 않음 |
| 위치 토큰 (seed 0) | 96.4% | 91.6% | 1단계에서는 이점 없음 |

- **이름 교체가 가장 효과가 컸다.** 위치 토큰을 써도 필요하다(빼면 미등장 이름 82~83%).
- **정규화(label smoothing, dropout)와 EMA는 모두 seed 간 편차(약 1.5%p) 안에서만 움직였다.** seed마다 다른 오답만
  10~17% 줄었고, 세 seed가 공통으로 틀리는 오답은 줄지 않았다. 1단계의 한계는 학습 방식이 아니라 데이터에 있다.
- **앙상블은 가장 높지만 쓰지 않는다.** 추론 비용이 3배이고, 작은 단일 모델을 이점으로 가져가는 방향과 맞지 않는다.
- **위치 토큰**(값 대신 "질문의 몇 번째 단어"를 출력)은 줄일 오답이 거의 없었다. 기본 모델의 값 오답이 이미 약 1%다.
  값이 여러 개인 2단계 질문에서 다시 비교한다.
- **학습을 더 길게 해도 오르지 않는다.** 학습 loss가 0이고, 마지막 5~6 epoch의 검증 EM이 ±0.5%p 안으로 평평하다.

## 4. 2단계로 넘기는 것

**전환 결정 (2026-10-07).** 계획서 3-3은 기준 미달이면 데이터를 보강해 반복하는 것이 원칙이지만, 예외로 2단계로 넘어간다.
학습 방식으로는 더 오르지 않았고(3절), 남은 오답의 원인(2절)은 라벨 규칙대로 원하는 비율의 질문을 만들 수 있는 2단계
질문 조합기에서 고치는 편이 1단계 LLM 데이터를 다시 만드는 것보다 근본적이다. 1단계 데이터를 2단계 학습에 20~30% 섞어
1단계 평가셋 점수를 계속 측정한다.

**가져갈 설정:** 이름 교체 40%, EMA 0.9995, 질문 조합기에서 라벨 규칙별 질문 비율 조정(존재 확인, `*`/식별 컬럼, 테이블 단서)

**이어서 할 일**

| 작업 | 내용 |
| --- | --- |
| 존재 확인 질문 채점 방식 | "do we carry a bench" → `SELECT *`처럼 의미상 맞지만 L1 관례와 다른 답을 어떻게 채점할지 정함 |
| 평가 보조 지표 | L5 문항 EM, SQL 단위 신뢰구간 (규칙 일치 EM은 반영 완료) |
| 조합기에 1단계 교훈 반영 | 존재 확인 비율, 복수형 속성 명사, 테이블 단서 표현 |
| 모델 축소 ablation | 4층·192차원. "데이터 대비 모델이 커서 암기한다"는 계획서 2장 우려 확인 |
| 제약 디코더 | DB 값·문법에 맞는 토큰만 생성. 게이트 판정은 미적용 수치로 하므로 판정에는 영향 없음 |
| 새 말투 · 사람 작성 평가 | 새 말투 출처를 둘 이상으로 늘려 범위로 보고. 사람 작성 질문 200개는 계획서대로 조합기 문장을 보기 전에 작성·봉인 |

**하지 않는 일**

| 작업 | 근거 (다시 볼 조건) |
| --- | --- |
| epoch 상한 늘리기 | 검증 EM이 이미 평평하고, 끝 무렵이 최고인 것은 cosine 학습률 때문이다 (모델 크기나 데이터 양이 바뀌면) |
| 단일 모델 정규화 추가 탐색 | 네 설정이 모두 같은 수준이었고 공통 오답에는 효과가 없다 (2단계에서 과적합이 다시 보이면) |
| 앙상블로 게이트 판정 | 추론 비용 3배, 작은 단일 모델 방향과 맞지 않음 |
| `soft_flags()`에 라벨 규칙 반영 | 병합 후 `clean_ambiguous --apply`가 같은 규칙으로 이미 지운다 (2단계에서 규칙 위반이 많아지면) |

| 항목 | 계획 | 실제 | 이유 |
| --- | --- | --- | --- |
| DB 행 수 | 80 / 40 / 150행 | 300 / 200 / 500행, 이름 풀 370 · 상품명 풀 240 | 원안으로는 ID 조건 30% 이하에서 학습 4,000 + 평가 1,000 SQL을 못 채움 |

| 미등장 값 평가셋 | — | Qwen3 생성본을 강한 LLM으로 재생성 | Qwen3 평가셋은 문형이 좁아 점수가 높게 나왔음(약 94% → 약 88%) |
| 평가 지표 | EM, 실행 정확도 | 다중 정답 EM 추가 | `*`와 이름 컬럼 중 무엇을 원하는지 질문만으로 알 수 없는 문항이 분포 내 6% |
| 분포 내 판정 기준 | 분포 내 평가셋 전체 EM | 라벨이 규칙과 다른 60문항을 뺀 규칙 일치 EM (전체 EM도 함께 보고) | 평가셋은 라벨 규칙 이전에 만들어 정제하지 않았고, 이 문항에서는 규칙대로 답하면 오답이 된다. 제외 판정은 학습 데이터 정제와 같은 함수(`clean_ambiguous`)가 질문과 정답만 보고 하며 모델 출력은 보지 않는다. 계획서 3-4의 판정 기준 조정(1회) |
| 새 말투 평가셋 | 다른 프롬프트로 만든 질문 | 다른 LLM이 요구사항 문서만 보고 생성 프롬프트를 직접 씀 | 우리가 프롬프트를 쓰면 학습 데이터 말투가 섞임 |
| 단계 전환 | 기준을 넘으면 다음 단계 | 기준 미달 상태에서 2단계 진행 | 4절 |
| 조기 종료 · 처리량 | — / 1.0~1.5e13 FLOPs/s | 10 epoch 개선 없으면 종료 / 2.7e12 | 검증 EM이 epoch마다 ±2%p 흔들림 / 작은 모델이라 커널 호출 오버헤드 비중이 큼 |

## 부록 A. 실험 상세

실험 코드와 체크포인트는 `stage2/`에 있다(`train_reg.py`, `ensemble_eval.py`, `pointer/`, `runs/`).

### A-1. 학습 방식 실험

모두 이름 교체 40%를 적용했다. 단일 모델은 seed 0/1/2 평균 ± 표준편차다.

| 설정 | 분포 내 (규칙 일치) | 분포 내 (전체) | 미등장 값 | 개체 / ID / 주문 ID |
| --- | --- | --- | --- | --- |
| 기본 모델 | 97.5 ± 0.2 | 96.5 ± 0.2 | 90.3 ± 0.6 | 89.7 / 89.5 / 95.2 |
| label smoothing 0.1 | 97.6 ± 0.2 | 96.6 ± 0.2 | 90.9 ± 0.9 | 90.2 / 90.1 / 96.1 |
| dropout 0.1 (임베딩·블록 출력의 residual) | 97.6 ± 0.1 | 96.7 ± 0.1 | 90.6 ± 1.0 | 89.9 / 90.3 / 95.3 |
| dropout 0.1 + label smoothing 0.1 | 97.5 ± 0.4 | 96.5 ± 0.4 | 89.9 ± 0.7 | 88.9 / 89.8 / 95.6 |
| EMA 0.999 | 97.6 ± 0.3 | 96.6 ± 0.3 | 90.7 ± 0.5 | 90.0 / 90.3 / 95.3 |
| EMA 0.9995 | 97.5 ± 0.3 | 96.5 ± 0.3 | 90.9 ± 0.5 | 90.2 / 90.9 / 95.4 |
| 3-seed 앙상블 (기본 모델) | 98.3 | 97.3 | 91.3 | 90.9 / 90.5 / 95.2 |
| 3-seed 앙상블 (label smoothing) | 98.2 | 97.2 | 91.6 | 91.1 / 90.3 / 96.8 |

- 앙상블은 다음 토큰 log 확률을 평균해 greedy 생성했다.
- seed별 오답 중 세 seed 공통 / seed 고유(평균)는 기본 모델 분포 내 98 / 85, 미등장 141 / 76개다. label smoothing은
  100 / 79, 138 / 66, dropout은 97 / 77, 146 / 63, EMA 0.9995는 105 / 77, 137 / 65로 고유 오답만 줄었다.
- EMA는 매 epoch 검증·체크포인트 선택·최종 평가를 EMA 가중치로 했다. EMA 0.9995의 seed별 미등장 값은 91.5 / 90.8 / 90.6%다.

### A-2. 위치 토큰 실험

질문의 단어마다 위치 표지를 붙이고, SQL의 이름·숫자 값 자리에 값 대신 표지를 출력한 뒤 질문 단어로 되돌린다
(`name = <w4>` → `name = 'harriet'`). 범주형 값은 그대로 쓴다. 값이 여러 단어여도 표지를 이어 쓰면 되므로 한 단어 이름 제약이
필요 없다. 질문에서 값을 찾지 못하는 학습 쌍(복수형 상품명, 0.3%)은 뺐다. seed 0 한 번씩이다.

| 실행 | 분포 내 (규칙 일치 / 전체) | 미등장 값 | 개체 / ID / 주문 ID |
| --- | --- | --- | --- |
| 순서 번호 표지(K번째 단어에 `<wK>`) + 이름 교체 40% | 96.4 / 95.4 | 91.6 | 91.2 / 91.1 / 94.8 |
| 순서 번호 표지, 이름 교체 없음 | 96.6 / 95.6 | 88.6 | 87.3 / 89.1 / 95.6 |
| 무작위 표지(예시마다 무작위) + 이름 교체 40% | 76.0 / 75.1 | 75.3 | 74.4 / 75.9 / 79.9 |

- 순서 번호 표지의 값 오답은 대부분 위치가 ±1~3칸 어긋난 것이다. 정답 위치가 12~17번째에 몰려 있는데, 학습 값의 약 5%만
  12번째 이후에 있다.
- 무작위 표지는 검증 EM이 55%에 머물다가 18 epoch에 77%로 계단식으로 뛰었다. 25 epoch 안에 표지 복사를 다 배우지 못했다.
- 이름 교체 없이는 미등장 이름이 고객 82% · 상품 83%로 떨어진다(교체하면 89% · 95%). 모델이 외운 이름 목록으로 값을 찾는다.
